## 1. 设计愿景与美学方向

### 目的

一页可独立阅读、可微信转发的顾问式说明页，面向 FBA 卖家，用客户经理的讲解逻辑阐明 4 个亚马逊售后功能的价值与开启方式。

### 基调选择：**咨询式资料页 / Editorial**

- 克制、可信、像整理过的方案材料，不是招商海报，不是电商落地页
- 有明显设计感但不过度炫技
- 适合微信截图传播

### 差异化

- 竞品通常是功能列表页或培训 PPT，我们用"问题链"叙事取代"功能清单"
- 用信息卡 + 流程图解替代伪后台截图，视觉更轻但信息更聚焦
- Prompt 导出功能是独有价值锚点

## 4. 详细实施步骤

### Step 1 — 搭建 HTML 骨架与锚点导航

- 桌面端：左侧固定锚点栏（章节标题 + 滚动高亮）
- 移动端：顶部横向滚动标签
- 章节锚点：`#hero` `#overview` `#bi` `#parts` `#partial` `#mfi` `#flow` `#resources` `#prompt`
- 响应式断点：768px

### Step 2 — Hero 区域

- 主标题：围绕"退货、退款、索赔"成本控制（待撰写文案）
- 副标题：点明面向 FBA 卖家、3-5 分钟读完
- 关键信息短句：客户经理整理版
- 主 CTA：`下载完整资料包`
- 次 CTA：`导出背景 Prompt`
- 背景：柔和渐变底色 + 细微噪点纹理，视觉关键词"编辑型"
- 动画：页面加载时 Hero 文字交错淡入（animation-delay 递进）

### Step 3 — 四功能总览区（Overview Cards）

- 四张横向排列的信息卡（移动端 2×2 网格）
- 每卡包含：
  - 功能中文名（大字）
  - 英文名（副标）
  - 一句话解释
  - 阶段标签（`买家支持` / `退货拦截` / `退款替代` / `入仓索赔`）
  - 配色区分（每个功能一个强调色，与全页统一）
- 卡片 hover：微微上浮 + 阴影加深
- 动画：四卡依次交错入场（staggered fade-in）

### Step 4 — 四个功能深度说明区

每个功能使用统一模块结构：

```
[功能图标 + 中文名 + 英文名]
├── 这是什么
├── 出现在哪里（触点列表或流程图）
├── 对卖家的收益（3 点 bullet）
└── 如何开启（步骤或条件）
```

**BI（品牌主实时支持）**
- 图标：Headset / MessageCircle
- 触点图：PLS 页面出现在订单页、退货流程、客服中心（用简单 SVG 流程图，不用伪截图）
- 收益 3 点
- 开启条件说明（需品牌备案 + 客服团队 + 联系账户经理）

**Parts（零配件补发）**
- 图标：Package / Wrench
- 买家旅程 4 入口可视化（用图示表达，不做 UI 截图）
- 收益：71% 顾客收到补件后保留商品（数据引用）
- 开启步骤：6 步简明流程图

**Partial Refund（部分退款）**
- 图标：Coins / Percent
- 退货流程分支图（系统分支示意，非 UI 截图）
- 收益 3 点
- 开启步骤（卖家后台路径）
- 注意：明确适用/不适用条件

**Proactive MFI Claim（货件差异调查）**
- 图标：Search / Shield
- 资格条件（$50/€49/£40 阈值说明）
- 追踪路径两条（货件页面 / 支持问题）
- 收益列表（无需手动申请、30 天赔付、防篡改胶带取消）

### Step 5 — 组合打法区（Flow Section）

- 横向流程图或纵向步骤链
- 四个阶段 + 箭头连接：BI → Parts → Partial Refund → Proactive MFI
- 底部注明：卖家可按需选择启用，不必全部同时开通
- 视觉：用 CSS 绘制流程节点 + 连接线，不用图片

### Step 6 — 资料扩展区

- 4 张资料信息卡（公众号文章 × 2、PPT × 1、DOCX × 1）
- 每卡：标题 + 类型标签 + 一句话说明 + 下载按钮
- 下载按钮：触发浏览器下载（若文件在本地相对路径）或跳转原文链接

### Step 7 — Prompt 导出交互

- 入口按钮：`导出背景 Prompt`
- 点击后：Modal 弹层展示结构化 Prompt 内容
- Prompt 包含：角色设定 + 背景资料 + 受众说明 + 语气要求 + 可替换任务位
- 两个动作按钮：`复制到剪贴板` + `下载 TXT`
- 复制成功后按钮文字变为"已复制 ✓"

### Step 8 — 页脚

- 资料来源说明
- 本页整理人/日期
- 免责声明（资料截止日期、建议以亚马逊官方为准）

### Step 9 — 细节打磨

- [ ] 平滑滚动（scroll-behavior: smooth）
- [ ] 锚点导航 active 状态高亮
- [ ] 滚动触发动画（Intersection Observer）
- [ ] 移动端触摸友好（按钮尺寸 ≥ 44px）
- [ ] 打印样式（@media print 优化）
- [ ] 深色模式（可选 @media (prefers-color-scheme: dark)）
- [ ] 无障碍：aria-labels、role、focus-visible 样式

## 7. 验收标准

1. 单 HTML 文件可在浏览器直接打开，桌面和移动端均可正常阅读
2. 四个功能的定义、收益、开启路径均清晰可读，不依赖原资料也能理解
3. 组合打法区形成"售后控制链"认知，不只是功能列表
4. 资料区有可操作的下载或链接
5. Prompt 导出能实际复制出结构化文本
6. 视觉上像"客户经理整理的方案页"，不是素材堆砌
7. 无控制台错误（Error level），无死链或 404 资源

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| 功能信息完整度不一致（BI/Parts 强，MFI 弱） | 用流程图解替代 UI 截图；明确边界，不伪造细节 |
| 卖家误以为 BI 可自助开通 | BI 区块明确标注需联系账户经理开通 |
| 卖家误以为需要全部开启 | 组合打法区 + 总览区均说明可按需选择 |
| 资料文件路径问题（本地分发） | 使用相对路径；HTML 放在顶层，`imported_from_desktop_tmp` 等放在 `assets/` 子目录 |
